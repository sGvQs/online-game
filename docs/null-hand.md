# Null Hand ゲーム仕様書

## 1. 概要
「Null Hand」は、ホスト（親）1人に対して複数人のゲスト（子）が挑む、非対称型の心理じゃんけんゲームです。参加ユーザー全員が1回ずつホストを経験するまでを「1試合（Match）」とし、最終的な獲得ポイントで勝敗（順位）を競います。

## 2. UI/UX デザイン（世界観）
* **カラースキーム**: 純粋な黒（`#000000`）と白系のグレー（`#FFFFFF` など）を基調とします。アクセントカラーとして赤（`#FF4444`）とシアン（`#44FFFF`）のみを使用します。
* **デザイン言語**: サイバーパンクやネオンの要素を完全に排除。PlayStationの『I.Q』のような、冷徹で無機質なソリッドデザイン。
* **フォント**: 等幅フォント（Monospace）を使用。システムログのような冷たいテキスト配置。
* **3Dオブジェクト**: React-Three-Fiber (R3F) を使用した手のモデルを採用。発光させず、純白のワイヤーフレーム、あるいは陰影の強いソリッドなマットホワイトで表現。

## 3. ゲームフロー

全員が1回ずつホストを担当するまで、以下のターン（ラウンド）を繰り返します。

1. **TITLE (待機・マッチ開始)**
   * ユーザーはタイトル画面で「READY」を押して待機します。
   * Title画面には世界ランキングの順位とポイントが表示されます。
   * 全員の準備が完了したら、ルームホストが「START」を押し試合が始まります。
2. **SETUP (ホストの設定)**
   * **ホストのみ**: 自分が出す「手の仮置き」を選択します。
   * 次に「ゲストに表示する偽装情報（嘘）」を以下の4つから選択し、内容を詳細設定します。
     * 「仮置きの手を偽る（INITIAL_HAND）」
     * 「変える確率を偽る（CHANGE_RATE）」
     * 「お気に入りの手を偽る（FAVORITE_HAND）」
   * 画面内には、ホストのロール説明と嘘をつくメリット（+3pt獲得）のアドバイスが表示されます。
3. **SHOWCASE (ゲストの確認)**
   * ゲスト全員にホストのステータス情報（嘘の情報が1つ混ざっている）が公開されます。
   * ゲストは情報を確認し、「CONFIRM（確認完了）」を押します。
4. **FINAL_DECISION (ホストの最終決定)**
   * ゲスト全員の確認が終わると、ホストに再び選択権が与えられます。
   * ホストは画面に大きく表示された「最初に選んだ手」を確認しつつ、そのままの手を出すか、違う手に変えるかを選択し「最終決定」を下します。
5. **BATTLE (ゲストの手選択)**
   * ホストの最終決定が完了すると、ゲスト全員が一斉に「ホストに勝つための手」を予想して選択します。
6. **RESULT (ターン結果とポイント集計)**
   * ホストの最終的な「手」と、各ゲストの「手」が公開され、それぞれの勝敗が白黒のハイコントラストUIで表示されます。
   * 一定時間後、次のホストに交代して「SETUP」に戻ります。全員がホストを終えていれば「GAME_OVER」へ進みます。
7. **GAME_OVER (最終結果発表)**
   * 試合の最終結果と順位が表示されます。
   * 終了ボタンで TITLE に戻ります。

## 4. ポイント（Score）とランキングシステム

### 試合中のポイント（MatchScore）取得ルール
* **ゲストの勝利**: ホストに勝ったゲストは **+1ポイント**。
* **ホストの完全勝利**: ゲスト全員に勝利した場合のみ、ホストに **+3ポイント**。

### 世界ランキングの計算ロジック
* `match_scores` テーブルに保存された累計ポイントの **総和（SUM）** をランキングポイントとしてそのまま使用します。
* 過去の勝率や勝利数（`janken_logs` に記録）も併記・保持されますが、順位の計算は純粋なポイントの合計値に基づきます。

## 5. 通信・アーキテクチャ
* Supabase Realtime (Postgres Changes) を利用し、`janken_events` テーブルの `INSERT/UPDATE` を監視します。
* Realtimeのペイロードから `phase` のみクライアント側ですぐに反映し（UX向上）、その後 Server Actions（`getLatestJankenEventWithStats`）で完全なデータを取得（Race Conditionを防ぐ）する設計としています。
