# 【大規模改修依頼】非対称型心理じゃんけんゲーム「Null Hand」のコアロジックおよびUI改修

## 1. 概要と改修の目的
現在開発中のNext.js + Supabase Realtime + React-Three-Fiber (R3F) を使用した非対称型オンライン心理戦ゲーム「Null Hand」の大規模な仕様変更を行います。

**【現状の課題】**
ホストが設定する「嘘（ブラフ）」の種類（初期値、確率など）が複雑すぎて、ゲスト側の認知負荷が高く「直感的な心理戦」が機能していません。

**【改修のゴール】**
ユーザーの選択肢を極限まで削ぎ落とし、**「システムが提示した二択を、ホストが反転させたか（REVERSE）、そのままか（STAY）」**を予想するだけのシンプルなバイナリ論理へ移行します。これに伴い、データベースのペイロード構造、状態遷移（ステート）、スコア計算ロジック、UIを全面的に書き換えます。

---

## 2. 新しい世界観とUI/UXガイドライン（変更なし・徹底事項）
* **トーン＆マナー**: PlayStationの『I.Q』のような、冷徹で無機質なソリッドデザイン。サイバーパンク感や過剰なネオンはNG。
* **カラースキーム**: 純黒（`#000000`）と純白（`#FFFFFF`）のハイコントラスト。アクセントにシアン（`#44FFFF`）と赤（`#FF4444`）のみ。
* **フォント**: 等幅フォント（Monospace）を用いたシステムログ表現。
* **3D演出 (R3F)**: 手のモデルは発光させず、純白のワイヤーフレームか陰影の強いソリッドなマットホワイト。

---

## 3. 新コアロジック：「Binary Reverse」システム

### 変更点
以前の「ホストが手と嘘の種類を選ぶ」フローを廃止し、以下のフローに書き換えます。

1. **DEAL (システム配牌 & 全員公開)**
   * システムが自動的に「本当の手（REAL）」と「嘘の手（BLUFF）」を生成し、全ユーザーの画面に公開する。
   * **【重要ロジック】**: 必ず「REALの手」は「BLUFFの手」に勝つ関係性になるよう生成する。（例: `REAL: [グー]`, `BLUFF: [チョキ]`）
2. **CHOICE (ホストの意思決定)**
   * ホストは、システムが提示した手を「そのまま（STAY）」にするか、「反転（REVERSE）」させるかだけを選択する。
   * STAYの場合: 最終的な手はREAL（例: グー）になる。
   * REVERSEの場合: 最終的な手はBLUFF（例: チョキ）になる。
3. **BATTLE (ゲストの手選択)**
   * ゲストは公開された2つの手と、画面に表示されるホストの「過去のREVERSE率（反転確率）」を見て、自分の手を1つ選ぶ。
4. **RESULT (結果発表とスコア集計)**
   * 決定した手を開示し、新スコアロジック（後述）に基づいてポイントを計算する。

---

## 4. 新スコア計算ロジック（重要）
「同じ手を出す（あいこ）」ことをシステムへの特大のボーナス献上（ペナルティ）と再定義します。1試合（全員がホストを1回経験）の合計ポイントでランキングを計算します。

| 状況 | ホスト獲得pt | ゲスト獲得pt | 判定条件 |
| :--- | :--- | :--- | :--- |
| **Null Hand (あいこ)** | **+5 pt** | **0 pt** | **1人でも**全員がホストと同じ手だった場合のみ発動。ホストとゲストが二人だけの時は発動しない。|
| **ゲスト単独勝利** | 0 pt | **+3 pt** | ホストに勝利したゲストが**1人のみ**の場合。 |
| **ゲスト通常勝利** | 0 pt | **+1 pt** | ホストに勝利したゲストが**複数人**いる場合。 |
| **ホスト完全勝利** | **+2 pt** | 0 pt | ゲスト全員が負け（またはあいこ）の場合。 |

## 5. データベース / 状態管理の変更要件
Supabaseのテーブル設計（特に `janken_events` などのペイロード）をこの新仕様に合わせて修正してください。

* **削除すべき項目**: ホストが選んでいた各種嘘のタイプ（`NONE`, `INITIAL_HAND`, `CHANGE_RATE`, `FAVORITE_HAND`）やその設定値。
* **追加すべき項目**:
  * 今回のシステムの提示手: `system_real_hand`, `system_bluff_hand`
  * ホストの選択: `host_choice` (`STAY` or `REVERSE`)
  * 統計データ: 各ユーザーの累計ホスト回数と、REVERSEを選択した回数（これを用いてUI上に「REVERSE RATE XX%」と表示するため）。
